> 文档状态：已确认
> 生效日期：2026-07-29
> 当前基线：`ef0782b`
> 目标：在不降低质量门禁的前提下，用最少交付批次完成路线图

## 1. 执行原则

速度通过以下方式提高：

```text
一次调查多个相邻阶段
一次形成完整设计
同一步并行开发
一次集成测试
一次真实环境验证
一次提交和路线图更新
```

质量门禁继续保留：

```text
证据
迁移
测试
真实验证
回滚
验收
追溯
```

## 4. 第2步：数据底座

### 合并范围

```text
P3 数据源与采集
P4 数据治理与分层存储
P5 DataContext与统一查询
```

### 纵向闭环

```text
DataSource
→ DataItem
→ CollectTask
→ RAW
→ CLEAN
→ Quality
→ Lineage
→ DataSnapshot
→ DataContext/API
```

### 并行工作流

- 数据目录和Tushare适配；
- 任务、重试、补采和幂等；
- RAW、CLEAN和版本；
- 数据质量、缺口和发布门禁；
- Lineage和Audit；
- DataContext、防未来和DataSnapshot；
- 数据库迁盘、压缩、归档和备份；
- API和管理接口；
- 自动测试与真实数据验收。

### 步骤完成标准

1. 首批日频、财务和事件数据可初始化和增量；
2. 分钟数据按批准范围运行；
3. 重跑不产生不可控重复；
4. RAW到CLEAN到质量可追溯；
5. 数据问题可补采、重洗和重新发布；
6. DataContext执行发布时间和可用时间规则；
7. 防未来测试通过；
8. 数据库不再依赖系统盘扩展分钟数据；
9. 备份和恢复演练通过；
10. 统一查询达到P2.4性能目标。

## 7. 第5步：实时与受控自动执行

### 合并范围

```text
P12 多用户、开放接口、实时桥接
P13 自动执行和高级智能
```

### 强制顺序

```text
资源审计
→ 实时数据验证
→ 券商桥接
→ 仿真
→ 模拟盘
→ 灰度实盘
→ 受控正式运行
```

任一步失败，不进入下一步。

### 步骤完成标准

- 多用户对象和AI上下文隔离；
- API不能绕过内部权限；
- 实时与历史数据语义一致；
- 券商状态同步和断线恢复通过；
- 自动执行有授权、风控、幂等、人工接管和紧急停止；
- 机器学习不存在已知未来泄漏；
- 任何真实订单都能回查到用户授权、信号、策略和数据。

## 10. 失败处理

一步内发现阻塞时：

- 不拆回原来的逐小专题讨论；
- 将阻塞项单独列出；
- 继续完成不受影响的并行工作；
- 阶段门禁仍以完整闭环为准；
- 关键外部资源缺失时，使用正式接口边界和Mock完成非外部部分；
- 外部能力不能用Mock冒充真实验收。
