## 5. P6对象和存储要求

### 5.1 Feature四层对象

必须分离：

```text
FeatureDefinition
FeatureVersion
FeatureRun
FeatureResultSet
```

含义：

- FeatureDefinition：稳定业务身份；
- FeatureVersion：不可变算法版本；
- FeatureRun：一次真实计算；
- FeatureResultSet：一次发布结果批次。

不得把“一个Python函数”直接当成完整Feature资产。

### 5.2 FeatureVersion最低绑定

至少绑定：

- feature_definition_id；
- version；
- implementation_ref；
- implementation_digest；
- code_commit；
- parameter_schema；
- default_parameters；
- input_dependencies；
- output_schema；
- frequency；
- lookback_window；
- available_at_policy；
- quality_policy_version；
- engine_version；
- created_at；
- status。

激活后的版本不得覆盖修改。修正必须新建版本。

### 5.3 Feature依赖

依赖对象必须支持：

```text
DataItem
FeatureVersion
AnalysisVersion
```

依赖关系进入Lineage。

任何FeatureResultSet必须能追溯到：

```text
DataSnapshot
FeatureVersion
参数快照
输入ResultSet
FeatureRun
代码提交
```

### 5.4 Feature结果存储

禁止：

```text
每新增一个Feature
=
新建一张全市场宽表
```

也禁止：

```text
每新增一个指标
=
复制一份全市场分钟数据
```

第一阶段采用：

```text
ResultSet批次
+
类型明确的窄表结果
```

数值型时序结果至少具备：

- result_set_id；
- security_code；
- observation_time；
- available_at；
- value；
- quality_status；
- created_at。

高维或大体积结果只能保存为受控Artifact，并在数据库登记摘要、Schema、Checksum和位置。

### 5.5 首批公共Feature

第一批以日线真实数据闭环为主，最低覆盖：

```text
return_1d
return_5d
return_20d
ma_deviation_5d
ma_deviation_20d
volatility_20d
turnover_mean_20d
volume_ratio_5d_20d
```

要求：

- 使用DataContext读取正式数据；
- 不读取RAW；
- 滚动窗口不足时显式为空或WARNING；
- 停牌、缺口、复权因子缺失必须显式处理；
- 输出available_at不能早于最后一个输入的available_at；
- 同一DataSnapshot、版本和参数重算结果一致。

OpenCode可以依据当前真实字段调整名称，但不得降低业务含义。

## 10. P8 A股规则与撮合要求

### 10.1 规则版本化

A股交易规则不能写成一套永久常量。

必须建立日期有效的：

```text
MarketRuleSet
MarketRuleVersion
```

规则至少根据以下维度匹配：

- 交易所；
- 板块；
- 证券类型；
- 风险警示状态；
- 上市阶段；
- 生效日期；
- 特殊无涨跌幅阶段；
- 交易单位；
- 结算和可卖日期规则。

规则来源和生效日期必须记录。

### 10.2 最低规则覆盖

最低覆盖：

- 交易日历；
- T+1可卖约束；
- 停牌；
- 涨停和跌停；
- 无涨跌幅限制阶段；
- 买卖数量和最小交易单位；
- 退市或不可交易状态；
- 现金不足；
- 持仓不足。

### 10.3 撮合口径

第一阶段以日线回测为主，默认使用明确的下一时点撮合：

```text
T日收盘后生成信号
→ T+1下一可交易时点撮合
```

禁止：

```text
使用T日收盘价生成信号
同时假设按T日收盘价成交
```

第一阶段至少支持：

```text
NEXT_OPEN
NEXT_CLOSE
```

使用NEXT_CLOSE时必须明确只消费成交前可知信息。

### 10.4 涨跌停成交

不能仅用“价格等于涨停价”判断一定无法成交。

第一阶段建立可配置且保守的FillPolicy，至少包括：

```text
STRICT_NO_FILL_AT_LOCKED_LIMIT
ALLOW_IF_BAR_HAS_TRADABLE_RANGE
```

默认使用保守口径，并在BacktestRun中绑定版本。

## 13. 回测防未来与复现

必须验证：

1. DataContext和DataSnapshot不读取未来available_at数据；
2. Feature只使用观察时间以前的输入；
3. 股票池只使用当时可知成员；
4. 财务数据按当时可用版本；
5. 信号时间早于成交时间；
6. 复权因子不使用未来修订；
7. 成本和交易规则按当时生效版本；
8. 同一输入指纹、引擎版本和代码提交重复执行结果一致；
9. 改变任一不可变输入会生成不同Run指纹；
10. 结果不存在当前成分回填历史的幸存者偏差。
