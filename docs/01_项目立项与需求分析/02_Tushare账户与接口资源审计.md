## 1. 审计结论

当前Tushare资源可以作为quantStock1首批数据底座的主数据源，但必须按“接口独立能力”管理，不能把Tushare视为一个没有边界的统一接口。

已确认事实：

1. 项目历史资源记录为2120积分；本次按用户要求不再核对权限中心，因此准确积分、购买主体和到期时间标记为未确认。
2. 当前Token实测可以调用普通积分接口，包括交易日历、股票基础信息、日线、复权因子、每日指标、停复牌、涨跌停价格、普通利润表和普通财务指标。
3. 当前Token实测具备A股历史分钟权限，`000001.SZ`至少可以取得2009-01-05起的1分钟数据。
4. 当前Token没有`income_vip`和`fina_indicator_vip`权限，财务数据只能按股票逐只采集，不能按报告期一次取得全市场。
5. `stk_limit`必须使用`offset`分页。实测第一页5800行，第二页1907行；只取第一页会静默漏数。
6. `trade_cal(exchange="BSE")`调用成功但返回0行，不能登记为北交所独立交易日历已支持。
7. 项目历史资源清单记录已购买`stk_auction_o`、`stk_auction_c`、`stk_auction`和`stk_mins`。本次只有`stk_mins`完成当前Token实测；集合竞价权限保持“历史记录已具备、当前Token未复核”。
8. 扩展数据域中的指数、板块、资金流向、龙虎榜、大宗交易、融资融券、股东和事件接口，官方存在相应接口，但当前Token未逐项实测，不作为首批架构的确定性前提。

## 2. 权限体系

Tushare权限分为两类。

### 2.1 积分接口

官方积分与通用频次：

| 积分等级 | 每分钟频次 | 每日总量 |
|---:|---:|---:|
| 120 | 50次 | 8000次 |
| 2000以上 | 200次 | 每个API 100000次 |
| 5000以上 | 500次 | 常规数据无总量限制 |
| 10000以上 | 500次 | 常规数据无上限，部分特色数据300次/分钟 |
| 15000以上 | 500次 | 特色数据无总量限制 |

有效调用频率必须取以下限制中的最小值：

```text
账户等级频率
接口专属频率
项目安全频率
```

例如：

- `stock_basic`接口专属上限为50次/分钟，项目当前配置为40次/分钟；
- `daily`接口页面标注500次/分钟，但2120积分历史记录对应账户通用上限为200次/分钟，项目当前配置为180次/分钟。

### 2.2 独立权限接口

独立权限与积分无关。与当前项目直接相关的官方规则：

| 权限 | 历史/更新时间 | 频次与单次限制 |
|---|---|---|
| A股历史分钟 | 2009年起；每日17:00—21:00处理完成 | 500次/分钟，8000行/次 |
| 集合竞价 | 当日开盘后可取；开盘、收盘接口每天更新 | 500次/分钟；开盘/收盘接口10000行/次 |
| 实时分钟 | 实时 | 500次/分钟，单次可请求多个标的 |

当前项目只确认了历史分钟真实可用。实时分钟不属于当前已确认资源。



`stk_auction_o`和`stk_auction_c`是当前官方文档中的明确接口。`stk_auction`是否为独立正式接口、历史别名或权限包名称，当前证据不足，不允许OpenCode直接依赖。

## 4. 核心接口限制

| 数据项 | API | 权限 | 单次限制 | 请求拆分 | 关键限制 |
|---|---|---|---:|---|---|
| 交易日历 | `trade_cal` | 2000积分 | 官方未在本次确认固定行数 | 交易所+日期范围 | BSE参数实测空返回 |
| 股票基础 | `stock_basic` | 2000积分 | 6000 | 上市状态+交易所 | 默认只取L会漏退市股票 |
| 日线 | `daily` | 120积分起 | 6000 | 交易日优先 | 未复权；停牌日不返回 |
| 复权因子 | `adj_factor` | 2000积分 | 6000（项目登记） | 交易日/股票 | 历史因子可能修订 |
| 每日指标 | `daily_basic` | 2000积分 | 6000 | 交易日 | 空值不能填0 |
| 停复牌 | `suspend_d` | 普通积分接口 | 未确认 | 交易日/股票 | 更新时间不定期 |
| 涨跌停价格 | `stk_limit` | 2000积分 | 5800 | `offset`分页 | 命中上限必须继续分页 |
| 历史分钟 | `stk_mins` | 独立权限 | 8000 | 股票+频率+时间窗口 | 时间参数必须带时分秒 |
| 利润表 | `income` | 2000积分 | 未确认 | 股票+报告期 | 当前无VIP，只能逐股 |
| 财务指标 | `fina_indicator` | 2000积分 | 100 | 股票+报告期 | 命中100必须缩小窗口 |
| 开盘竞价 | `stk_auction_o` | 独立权限 | 10000 | 交易日 | 当前Token未复核 |
| 收盘竞价 | `stk_auction_c` | 独立权限 | 10000 | 交易日 | 当前Token未复核 |

## 5. 字段单位和时间规则

日线和分钟的成交量、成交额单位不同：

```text
daily.vol       = 手
daily.amount    = 千元
stk_mins.vol    = 股
stk_mins.amount = 元
```

标准层转换：

```text
daily.volume_share = daily.vol × 100
daily.amount_cny   = daily.amount × 1000

minute.volume_share = stk_mins.vol
minute.amount_cny   = stk_mins.amount
```

分钟时间参数必须使用：

```text
YYYY-MM-DD HH:MM:SS
```

仅给`end_date=YYYY-MM-DD`时，官方说明返回范围不包括`end_date`当天。

日常更新时间：

| 数据 | 官方更新时间 |
|---|---|
| 复权因子 | 盘前约9:15—9:20 |
| 涨跌停价格 | 盘前约8:40 |
| 日线 | 15:00—16:00 |
| 每日指标 | 15:00—17:00 |
| 历史分钟 | 17:00—21:00 |
| 停复牌 | 不定期 |
| 财务数据 | 随公告发布并可能修订 |

## 6. 完整性规则

以下返回量命中时必须视为“可能截断”：

```text
100
5800
6000
8000
10000
```

处理顺序：

1. 有分页参数时继续分页；
2. 无分页时按日期、交易所、股票、报告期或时间窗口拆小；
3. 所有子请求完成后按业务主键去重；
4. 与证券主数据、交易日历和预期股票范围交叉核对；
5. 完整性确认后才允许发布到正式数据层。

空返回不能直接解释为没有业务数据。至少要区分：

```text
真实无数据
参数不支持
权限不足
数据尚未更新
股票未上市或已退市
停牌
日期边界错误
来源延迟
```

## 7. 许可和Token边界

官方权限说明区分个人与机构价格，并对分钟数据用途作出研究学习限制。当前购买主体、权限到期时间和商业授权范围按用户要求不再核对，状态保持未确认。

强制边界：

- 当前阶段只按研究平台使用假设进行技术准备；
- 在公司经营、客户服务、对外收费或正式生产使用前，必须重新确认数据授权；
- Token只能通过环境变量或密钥管理注入；
- 日志、错误、数据库和文档不得保存明文Token；
- 不得通过并发、账号共享或其他技术方式规避官方限制。

## 8. 对OpenCode的强制输入

OpenCode必须：

1. 为每个接口单独配置权限、频率、行数上限、分页、拆分维度、更新时间和历史范围；
2. 把“HTTP成功”和“数据完整”分开；
3. 对命中上限、空返回、权限错误、限频错误和字段变化建立独立状态；
4. 日线和分钟使用不同单位转换；
5. 分钟按股票、频率和时间窗口采集，支持动态缩窗；
6. 财务数据按公告可见时间和版本保存，防止未来数据泄漏；
7. 把`stk_limit`登记为支持offset分页；
8. 不把`trade_cal(BSE)`登记为已验证；
9. 不调用当前无权限的财务VIP接口；
10. 不把未实测扩展接口纳入首批验收范围。

OpenCode不得自行假设：

```text
准确积分
权限到期时间
购买主体
商业授权
所有接口均为500次/分钟
所有A股接口都支持BSE
集合竞价当前Token仍有效
未实测扩展接口当前Token可用
```
