> 路线图阶段：P1.3

> 当前仓库提交：`fa0126e`
> 审计时服务器运行代码：`b95af7dd0c708654d855316145456adc54e89c1d`

> 证据文件：`evidence/quantstock1_svr3_environment_facts_20260728.json`

## 1. 专题结论

本专题已经完成对`svr3`服务器资源、容器运行环境、数据库物理位置、服务端口、外部数据源连通性、备份恢复证据和安全边界的统一审计。

结论分为两层：

### 1.1 当前可以确认

1. 服务器可以继续承担quantStock1开发、接口验证、样本采集和小规模性能验证。
2. API、PostgreSQL、Worker和Scheduler当前均在运行。
3. API只绑定服务器回环地址`127.0.0.1:18000`，当前不会直接从其他主机访问。
4. PostgreSQL宿主机端口绑定`0.0.0.0:5432`和`[::]:5432`，即监听全部IPv4和IPv6网卡。
5. 数据库物理卷位于Docker根目录下，实际占用系统盘`/`，不在项目代码所在的`/mnt/1t_back`，也不在`/mnt/2t_ssd`。
6. 系统盘使用率为72%，`/mnt/2t_ssd`和`/mnt/1t_back`仍有较大剩余空间。
7. 服务器可以正常访问Tushare HTTPS接口。
8. 数据库备份、恢复演练、异机备份、访问白名单、数据库TLS、主机防火墙和集中监控均没有取得确认依据。
9. 服务器没有发现OpenCode可执行程序；OpenCode不应被设计成服务器运行依赖。

### 1.2 当前不能认定

当前证据不足以认定`svr3`已经满足正式生产环境要求。

阻断生产认定的事实包括：

- 操作系统是CentOS Linux 8，该版本已经停止官方更新；
- 数据库位于使用率72%的系统盘；
- PostgreSQL监听全部宿主机网卡；
- 防火墙、`pg_hba.conf`、数据库TLS和来源IP限制未确认；
- 备份任务、保留周期、异机备份和恢复演练未确认；
- 容器资源限制、日志轮转、集中监控和告警未确认；
- 当前只有样本数据，尚未完成全量容量和长期压力验证。

因此，本专题完成的是“现状审计和边界确认”，不是“生产环境验收”。

| 内核 | `4.18.0-553.97.1.el8_10.x86_64` |
| 架构 | `x86_64` |
| 时间证据 | 命令输出为`+08:00` |
| Docker可见CPU | 4 |
| 内存总量 | 约62 GiB |
| 当前可用内存 | 约53 GiB |
| Swap总量 | 约15 GiB |

“Docker可见CPU为4”不等同于已经确认物理服务器只有4个CPU核心。当前没有取得CPU型号、物理插槽、超线程和宿主机资源限制来源。

CentOS官方资料确认，CentOS Linux 8已于2021年12月31日结束生命周期，之后不再提供该版本内容更新。因此该操作系统不能作为长期生产运行的默认基线。

## 3. 磁盘与数据位置

| 挂载点 | 文件系统 | 容量 | 已使用 | 剩余 | 使用率 |
|---|---|---:|---:|---:|---:|
| `/` | XFS | 937 GiB | 671 GiB | 266 GiB | 72% |
| `/mnt/2t_ssd` | XFS | 1.9 TiB | 852 GiB | 1.1 TiB | 45% |
| `/mnt/1t_back` | XFS | 932 GiB | 164 GiB | 768 GiB | 18% |

项目代码：

```text
/mnt/1t_back/project/quantstock1
```

Docker根目录：

```text
/var/lib/docker
```

PostgreSQL数据卷：

```text
/var/lib/docker/volumes/quantstock1-dev_quantstock1_dev_pgdata/_data
```

这三个路径说明：

```text
项目代码位于 /mnt/1t_back
数据库位于 /var/lib/docker
/var/lib/docker 位于系统盘 /
```

当前数据库逻辑大小约78 MiB，物理Docker卷约169 MiB，体量仍很小。这只能说明当前样本库占用较小，不能证明全量历史库可以继续长期放在系统盘。

### 3.1 存储边界结论

P1.3不直接决定数据库迁移。

P1.5容量评估完成前，OpenCode必须把数据库路径视为可配置资源，不得把当前系统盘路径固化为最终架构。

后续决策候选：

- 数据库主数据放在`/mnt/2t_ssd`；
- 备份放在`/mnt/1t_back`；
- WAL、临时文件、Docker镜像和业务数据是否分开；
- 是否启用TimescaleDB压缩和归档。

这些都是后续设计项，不是本次已批准实施方案。

## 5. 服务拓扑与端口

| 服务 | 当前状态 | 宿主机端口 |
|---|---|---|
| API | 运行中 | `127.0.0.1:18000 -> 8000` |
| PostgreSQL/TimescaleDB | 运行中且健康 | `0.0.0.0:5432`、`[::]:5432` |
| Worker | 运行中 | 无公开端口 |
| Scheduler | 运行中 | 无公开端口 |

逻辑关系：

```text
Scheduler
    ↓
任务数据库
    ↓
Worker
    ↓
Tushare
    ↓
PostgreSQL/TimescaleDB

本机管理工具
    ↓
127.0.0.1:18000
    ↓
API
```

### 5.1 API边界

API绑定`127.0.0.1`是当前明确的最小暴露面。

在没有完成身份认证、TLS、反向代理、来源限制和审计前，不得把API直接改为`0.0.0.0`对外开放。

### 5.2 数据库边界

PostgreSQL官方说明：

```text
0.0.0.0 = 监听全部IPv4地址
::      = 监听全部IPv6地址
```

这只表示监听范围，不等同于已经暴露到互联网。外部是否真实可达还取决于：

```text
服务器网络位置
上级网络设备
主机防火墙
安全组
pg_hba.conf
数据库认证
```

上述控制本次均未取得完整证据。

当前最重要的风险不是“已经确认数据库被互联网访问”，而是“数据库监听范围大于当前业务已证明的需要，且外围控制未确认”。

## 6. 外部网络与Tushare连通性

服务器可以解析并访问：

```text
api.tushare.pro
```

|---|---:|
| DNS | 0.004秒 |
| TCP连接 | 0.004秒 |
| TLS | 0.170秒 |

该结果只能证明审计时连通正常，不能证明：

- 带宽能力；

- DNS故障恢复；
- Tushare限频；

## 8. 当前数据规模边界

当前正式数据主要为样本：

- 日线只有1个交易日；
- 分钟数据只有1个交易日、101只股票；
- 数据库逻辑大小约78 MiB；
- 分钟超表只有1个chunk；
- 尚未形成全市场、全历史和长期增量规模。

所以当前环境尚不能回答：

```text
全量初始化需要多久
历史分钟最终占用多少磁盘
高并发查询是否稳定
备份窗口多长
恢复时间多长
7天chunk是否合理
是否必须压缩
系统盘还能支撑多久
```

这些问题归入P1.5容量与性能专题。

## 9. 密钥和配置边界

审计确认以下配置以环境变量名称存在：

```text
QUANTSTOCK1_DATABASE_URL
QUANTSTOCK1_DB_PASSWORD
QUANTSTOCK1_TUSHARE_TOKEN
QUANTSTOCK1_ENV
QUANTSTOCK1_LOG_LEVEL
QUANTSTOCK1_API_PORT
QUANTSTOCK1_WORKER_LEASE_SECONDS
QUANTSTOCK1_WORKER_POLL_SECONDS
```

审计证据没有保存密码和Token明文。

当前只能确认“运行时通过环境变量取得配置”，不能确认：

- 环境变量来自受保护的密钥系统；
- `.env`文件权限是否合格；
- Docker inspect权限是否受控；
- 日志是否完全脱敏；
- 密钥是否定期轮换；
- 开发、测试和生产是否使用不同凭据。

### 9.1 强制边界

OpenCode必须遵守：

1. Token和数据库密码不得写入仓库；
2. 日志和错误响应不得输出完整密钥；
3. 测试数据和文档不得包含真实Token；
4. 生产配置必须与开发配置隔离；
5. 密钥注入方式必须可替换为正式密钥管理方案；
6. 不得因为当前环境变量可用就认定密钥治理已经完成。

## 12. OpenCode实际运行边界

服务器检查未发现`opencode`命令。

项目约定：

```text
OpenCode是开发和设计执行工具
但不是quantStock1生产运行组件
```

因此：

- 不要求在`svr3`安装OpenCode；
- OpenCode不能成为API、Worker、Scheduler或数据库启动依赖；
- OpenCode产生的代码和文档必须通过Git仓库进入服务器；
- 服务器部署只运行经过提交和审核的项目产物。

## 13. 风险分级

### P0：生产化前必须解决

1. CentOS Linux 8已经停止官方维护；
2. 数据库备份和恢复能力未确认；
3. PostgreSQL监听全部宿主机网卡，外围访问控制未确认；
4. 数据库位于使用率72%的系统盘；
5. 生产密钥管理方式未确认。

### P1：进入全量数据前必须解决

1. 完成全量容量和性能评估；
2. 确定数据库最终磁盘位置；
3. 确定TimescaleDB chunk和压缩策略；
4. 建立日志轮转、磁盘监控和任务告警；
5. 明确资源限制和并发上限；
6. 明确开发、验证和生产环境隔离方式。

### P2：正式运维前完善

1. 形成标准部署和回滚手册；
2. 建立定期安全检查；
3. 建立依赖和镜像升级机制；
4. 建立故障演练和恢复报告；
5. 建立容量趋势和成本记录。


```text

监控告警

```

## 15. 对OpenCode的强制设计输入

OpenCode后续设计必须满足：

1. 当前compose仅作为开发环境基线，不直接复制为生产方案；
2. API默认保持本机绑定，外部访问必须经过受控入口；
3. 生产数据库默认不发布宿主机端口，确需管理访问时使用明确白名单；
4. 数据库物理路径必须配置化；
5. 不能把`/var/lib/docker`系统盘位置写死为最终存储；
6. 容器必须支持CPU、内存、日志和健康检查配置；
7. 数据库、API、Worker和Scheduler的配置必须区分环境；
8. 密钥不得写入代码、镜像或Git；
9. 备份必须形成可恢复验证，而不是只生成文件；
10. TimescaleDB压缩、chunk和保留策略必须由P1.5数据结果决定；
11. 服务器不安装OpenCode也必须能够独立部署和运行；
12. 所有生产化变更必须有回滚方案。

OpenCode不得自行假设：

```text
当前CentOS 8可以长期安全运行
5432监听全部网卡是业务必须
存在/backup目录就已经完成备份
系统盘剩余266 GiB一定足够
4个Docker可见CPU就是物理服务器全部CPU
当前样本性能可以代表全量性能
当前7天chunk是最终值
当前未压缩是最终策略
当前环境变量方式已经达到生产密钥管理要求
```
