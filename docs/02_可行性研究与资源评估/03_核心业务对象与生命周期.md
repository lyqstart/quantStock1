# 核心业务对象与生命周期

> 路线图阶段：P2.2 核心业务对象与生命周期
> 项目：A股量化研究与信号决策平台
> 形成日期：2026-07-29
> 状态：已确认
> 当前仓库基线：`f4add37`
> 适用范围：V1总体设计，并为V2、V3保留稳定边界

## 1. 文档目的

本文件定义平台核心业务对象、对象身份、版本、状态、归属和生命周期。

本文件不要求当前一次性开发全部对象。它解决的是：

1. 哪些对象是长期稳定的业务身份；
2. 哪些对象必须单独版本化；
3. 哪些对象代表一次真实执行；
4. 哪些结果完成后不可覆盖；
5. 数据、研究、策略、回测、风控、信号和决策如何连接；
6. 当前已经实现的对象与未来目标对象如何区分；
7. 如何避免后续因多用户、实时和实盘扩展推翻底层模型。

核心原则：

```text
对象有唯一身份
版本不可被静默覆盖
执行历史永久保留
状态流转有规则
归属和环境明确
结果能够追溯到上游
```

```text

```

当前 `lineage` schema没有基础表。

当前已确认的数据处理链：

```text

↓
```

## 4. 对象建模规则

### 4.1 稳定对象与版本对象分离

稳定对象表示“它是什么”。

版本对象表示“这次正式采用的具体定义是什么”。

例如：

```text
StrategyDefinition
↓
StrategyVersion
```

不能把策略名称、代码、参数和状态全部放在一条可覆盖记录中。

### 4.2 业务目标与执行实例分离

```text
Task = 要完成什么
Run  = 某一次真实执行
```

失败后重试不能覆盖原失败记录。

### 4.3 执行与结果集合分离

```text
Run
↓
ResultSet / Batch
```

Run表示动作，Batch或ResultSet表示动作处理或产生的数据集合。

### 4.4 正式结果不可覆盖

以下对象进入终态后不可原地改写核心内容：

- RawBatch；
- CleanBatch；
- DataSnapshot；
- FeatureResultSet；
- AnalysisResultSet；
- StockPoolVersion；
- StrategyVersion；
- BacktestRun；
- RiskEvaluation；
- Signal；
- UserDecision；
- Order和Fill。

需要修正时创建新对象、新版本或新执行记录。

### 4.5 状态与事实分离

当前状态便于查询。

状态变化历史必须进入AuditEvent。

不能只保留最终状态。

## 5. 统一身份字段

正式对象按类型选用以下字段：

```text
object_id
object_code
version_id
version_no
run_id
batch_id
trace_id
owner_user_id
created_by
environment_id
status
created_at
updated_at
```

字段语义：

| 字段 | 作用 |
|---|---|
| `object_id` | 稳定对象身份 |
| `object_code` | 人可识别、命名空间内稳定编码 |
| `version_id` | 不可变版本身份 |
| `run_id` | 一次真实执行 |
| `batch_id` | 一批数据或结果集合 |
| `trace_id` | 一条跨模块业务链 |
| `owner_user_id` | 对象归属 |
| `environment_id` | dev、test、prod等环境 |
| `status` | 当前业务状态 |

内部主键优先使用UUID。

外部代码、Tushare代码、券商订单号等必须单独保存，不能作为平台内部唯一身份。

## 6. 目录与来源对象

### 6.1 DataSource

表示外部或内部数据来源。

当前已确认正式主数据源：

```text
Tushare
```

未来其他来源必须经过独立审计后才能进入正式目录。

核心属性：

```text
data_source_id
source_code
source_name
source_type
credential_ref
health_status
status
created_at
updated_at
```

生命周期：

```text
DRAFT
↓
ENABLED
├─ DEGRADED
├─ DISABLED
└─ RETIRED
```

`credential_ref`只保存密钥引用，不保存明文Token。

### 6.2 DataItem

表示平台长期管理的一种业务数据。

例如：

```text
stock_daily
stock_minute
financial_income
```

DataItem不是某个外部接口，也不是某张物理表。

核心属性：

```text
data_item_id
data_item_code
name
domain
object_type
grain
frequency
business_time_field
availability_rule
update_mode
retention_class
schema_version
quality_policy_ref
status
```

生命周期：

```text
DRAFT
↓
VALIDATED
↓
ACTIVE
↓
DEPRECATED
↓
RETIRED
```

### 6.3 SourceBinding

表示某个DataItem如何从某个DataSource取得。

核心属性：

```text
source_binding_id
data_item_id
data_source_id
binding_code
provider_api
request_policy_version
field_mapping_version
permission_type
capability_status
priority
status
```

生命周期：

```text
UNKNOWN
↓
AVAILABLE
├─ RATE_LIMITED
├─ TEMPORARILY_UNAVAILABLE
├─ PERMISSION_DENIED
├─ SCHEMA_CHANGED
├─ DISABLED
└─ RETIRED
```

DataItem状态与SourceBinding状态必须分离。

### 6.4 StoragePolicy

表示DataItem在RAW、CLEAN、归档、压缩和备份中的存储规则。

核心属性：

```text
storage_policy_id
data_item_id
policy_version
raw_retention
clean_retention
archive_rule
compression_rule
partition_rule
backup_class
status
```

StoragePolicy正式变更必须产生新版本。

## 7. 采集与运行对象

### 7.1 CollectionTaskDefinition

对应当前 `ops.task_definition`。

它定义可重复产生采集任务的规则，不代表某一次采集。

核心属性：

```text
task_definition_id
task_code
data_item_id
source_binding_id
run_type
schedule_rule
availability_rule
split_policy_version
retry_policy_version
priority
enabled
```

当前V1保留 `enabled` 作为最小状态。

未来需要完整生命周期时使用：

```text
DRAFT
ACTIVE
PAUSED
RETIRED
```

### 7.2 CollectTask

表示明确、有限、可验收的采集业务目标。

例如：

```text
stock_daily
2026-07-24
全市场
INCREMENTAL
```

统一run_type：

```text
INITIALIZE
INCREMENTAL
BACKFILL
REPAIR
RETRY
RERUN
PROBE
MIGRATION
```

状态：

```text
PENDING
RUNNING
WAITING_SOURCE
WAITING_RATE_LIMIT
WAITING_DEPENDENCY
CAPACITY_BLOCKED
PAUSED
PARTIAL
SUCCEEDED
FAILED
CANCELLED
```

终态任务不能直接重新改成RUNNING。

重新执行应创建新Run或新的RERUN任务。

### 7.3 CollectRun

表示CollectTask的一次真实执行。

状态：

```text
CREATED
RUNNING
SUCCEEDED
PARTIAL
FAILED
CANCELLED
LOST
```

LOST表示执行进程失联，不等于正常业务失败。

### 7.4 RequestSlice

表示CollectTask内可以独立执行和恢复的最小业务范围。

状态：

```text
PENDING
RUNNING
SUCCEEDED
FAILED
RETRY_WAIT
SPLIT
CANCELLED
LOST
```

父Slice进入SPLIT后不再执行，由全部叶子Slice决定业务范围是否完整。

### 7.5 SliceAttempt

表示一次真实外部请求。

状态：

```text
RUNNING
SUCCEEDED
FAILED
```

每次重试形成新Attempt，不覆盖旧Attempt。

### 7.6 WorkerRegistry和SchedulerState

Worker状态：

```text
STARTING
ONLINE
DRAINING
OFFLINE
LOST
```

Scheduler状态：

```text
STARTING
LEADER
STANDBY
DRAINING
OFFLINE
LOST
```

Worker和Scheduler是运行对象，不是业务资产。

## 8. 原始与标准数据对象

### 8.1 RawBatch

表示一次或一组来源请求形成的原始数据集合。

核心属性：

```text
raw_batch_id
collect_run_id
slice_attempt_id
data_item_id
source_binding_id
request_hash
record_count
schema_fingerprint
content_hash
fetched_at
status
```

状态：

```text
RECEIVED
VALIDATING
ACCEPTED
QUARANTINED
REJECTED
ARCHIVED
```

RAW保留来源事实，不承担平台标准口径。

### 8.2 RawRecord

RawRecord保留：

- 外部原始字段；
- 来源记录键；
- RawBatch引用；
- 来源时间；
- 平台接收时间；
- 原始内容哈希。

RawRecord可以采用按DataItem独立表，不要求建设通用JSON大表。

### 8.3 CleanBatch

表示RAW经过指定规则版本后形成的标准化结果批次。

核心属性：

```text
clean_batch_id
data_item_id
clean_rule_version
schema_version
started_at
finished_at
input_count
accepted_count
skipped_count
rejected_count
status
```

状态：

```text
PENDING
PROCESSING
PASSED
WARNING
FAILED
QUARANTINED
INVALIDATED
ARCHIVED
```

### 8.4 CleanRecordVersion

CLEAN正式记录使用业务主键，并保留：

```text
business_key
business_time
available_at
valid_from
valid_to
is_current
source_version
clean_batch_id
quality_status
```

财务修订、来源更正和规则重洗不得直接删除历史版本。

### 9.1 QualityRun

表示对明确数据范围执行的一次质量检查。

状态：

```text
PENDING
RUNNING
PASSED
WARNING
FAILED
CANCELLED
```

### 9.2 QualityIssue

表示一条可定位、可处置的质量问题。

核心属性：

```text
quality_issue_id
quality_run_id
data_item_id
scope
rule_code
severity
status
reason
detected_at
resolved_at
```

状态：

```text
OPEN
ACKNOWLEDGED
RESOLVING
RESOLVED
WAIVED
```

WAIVED必须记录批准人和原因。

### 9.3 DataGap

表示已确认的数据缺口。

状态：

```text
OPEN
PLANNED
BACKFILLING
VERIFIED
CLOSED
```

### 9.4 DataWatermark

表示某DataItem、范围和频率当前推进到哪里。

至少区分：

```text
latest_collected
latest_clean
latest_quality_passed
expected
```

Watermark是运行汇总，不替代真实批次和质量事实。

## 10. 数据上下文对象

### 10.1 DataContext

DataContext是一次查询或计算的语义值对象。

至少包含：

```text
as_of_time
available_at_cutoff
market_scope
security_scope
frequency
adjustment_policy
quality_policy
data_version_policy
environment_id
```

DataContext不等于DataSnapshot。

### 10.2 DataSnapshot

DataSnapshot是为了研究和回测复现而冻结的正式数据视图。

核心属性：

```text
data_snapshot_id
snapshot_code
as_of_time
available_at_cutoff
data_item_versions
quality_policy_version
created_by_run_id
content_fingerprint
status
```

状态：

```text
BUILDING
READY
INVALIDATED
ARCHIVED
```

READY后核心内容不可覆盖。

INVALIDATED只表示不再适合作为新研究输入，不能删除已经引用它的历史回测。

## 11. 特征与分析对象

### 11.1 FeatureDefinition和FeatureVersion

FeatureDefinition表示业务含义。

FeatureVersion表示不可变计算逻辑。

版本状态：

```text
DRAFT
TESTING
VALIDATED
ACTIVE
DEPRECATED
RETIRED
```

### 11.2 FeatureRun和FeatureResultSet

FeatureRun表示一次计算。

FeatureResultSet表示该次计算产生的结果集合。

结果必须绑定：

```text
feature_version_id
data_snapshot_id
parameter_snapshot
run_id
content_fingerprint
```

### 11.3 AnalysisDefinition和AnalysisVersion

Analysis用于高于基础特征的综合判断、评分、标签和结构识别。

同样采用：

```text
Definition
Version
Run
ResultSet
```

四层分离。

## 12. 股票池与策略对象

### 12.1 StockPool

表示稳定的股票集合业务定义。

例如：

```text
全A股
自选池
策略候选池
今日关注池
```

### 12.2 StockPoolVersion

表示某个时点不可变的成员快照。

必须记录：

```text
stock_pool_version_id
stock_pool_id
effective_at
member_fingerprint
generation_rule_version
input_snapshot_id
```

历史回测不得使用当前成员替代历史成员。

### 12.3 StrategyDefinition

表示策略业务目标、适用范围、输入和输出契约。

### 12.4 StrategyImplementation

表示具体代码实现。

至少记录：

```text
repository
commit_sha
entrypoint
runtime
dependency_lock
implementation_fingerprint
```

### 12.5 StrategyVersion

将StrategyDefinition、StrategyImplementation、默认参数和依赖版本冻结为正式版本。

状态：

```text
DRAFT
TESTING
VALIDATED
ACTIVE
DEPRECATED
RETIRED
```

已经被正式回测或信号引用的版本不能物理覆盖。

## 13. 研究任务与回测对象

### 13.1 ResearchTaskDefinition

用于定义重复研究或策略运行规则。

它与CollectionTaskDefinition分开，避免“采集任务”和“研究任务”混为一类。

### 13.2 ResearchTaskRun

每次真实运行形成独立对象。

状态：

```text
PENDING
RUNNING
SUCCEEDED
PARTIAL
FAILED
CANCELLED
LOST
```

必须绑定：

```text
research_task_definition_id
strategy_version_id
data_snapshot_id
stock_pool_version_id
parameter_snapshot
trace_id
```

### 13.3 BacktestRun

BacktestRun是不可变研究事实。

必须绑定：

```text
strategy_version_id
data_snapshot_id
stock_pool_version_id
parameter_snapshot
time_range
cost_model_version
risk_rule_version
runtime_version
code_commit
```

状态：

```text
QUEUED
RUNNING
SUCCEEDED
PARTIAL
FAILED
CANCELLED
INVALIDATED
```

INVALIDATED表示后来发现输入或规则问题，不删除历史结果。

## 14. 风控、信号与用户决策对象

### 14.1 TradePlan

策略结果不能直接成为信号或订单。

先形成TradePlan。

状态：

```text
DRAFT
READY_FOR_RISK
RISK_PASSED
RISK_BLOCKED
SIGNALLED
EXPIRED
CANCELLED
```

### 14.2 RiskRuleSet和RiskRuleVersion

风险规则采用定义与版本分离。

每次正式风控必须绑定具体RiskRuleVersion。

### 14.3 RiskEvaluation

每次风控检查形成不可变结果。

核心属性：

```text
risk_evaluation_id
trade_plan_id
risk_rule_version_id
input_state_snapshot
result
reasons
checked_at
```

同一TradePlan可以有多次RiskEvaluation，不能互相覆盖。

### 14.4 Signal

只有符合发布条件的TradePlan才能形成Signal。

状态：

```text
GENERATED
PUBLISHED
ACKNOWLEDGED
EXPIRED
CANCELLED
CLOSED
```

用户接受或拒绝不是Signal状态，属于UserDecision。

### 14.5 UserDecision

V1最终由用户作出决定。

决策类型：

```text
ACCEPTED
REJECTED
ADJUSTED
IGNORED
```

UserDecision记录：

```text
decision_id
signal_id
user_id
decision_type
adjustment
reason
decided_at
```

系统建议与用户决定必须永久区分。

## 15. V2和V3执行对象

V1不正式启用真实执行。

为V2、V3预留：

```text
Account
ExecutionIntent
Order
Fill
Position
ReconciliationRun
```

```text
UserDecision / 自动授权
↓
ExecutionIntent
↓
Order
↓
Fill
↓
Position
↓
ReconciliationRun
```

外部券商ID不得替代平台内部ID。

AI不得直接创建可执行订单。

## 16. 用户、归属和共享

当前是单用户平台，但新建核心对象必须预留：

```text
owner_user_id
created_by
updated_by
visibility
workspace_id
```

visibility：

```text
PRIVATE
SHARED
SYSTEM
```

V1默认：

```text
owner_user_id = 当前用户
visibility = PRIVATE或SYSTEM
```

不建设复杂组织权限，但不允许新对象完全没有归属字段。

## 18. 统一生命周期模式

### 18.1 定义类对象

```text
DRAFT
↓
VALIDATED
↓
ACTIVE
↓
DEPRECATED
↓
RETIRED
```

适用：

- DataItem；
- FeatureDefinition；
- AnalysisDefinition；
- StrategyDefinition；
- RiskRuleSet。

### 18.2 版本类对象

```text
DRAFT
↓
TESTING
↓
VALIDATED
↓
ACTIVE
↓
DEPRECATED
↓
RETIRED
```

ACTIVE后内容不可覆盖。

### 18.3 执行类对象

```text
PENDING / QUEUED
↓
RUNNING
├─ SUCCEEDED
├─ PARTIAL
├─ FAILED
├─ CANCELLED
└─ LOST
```

终态不可原地返回RUNNING。

### 18.4 数据批次类对象

```text
RECEIVED / BUILDING
↓
VALIDATING / PROCESSING
├─ ACCEPTED / PASSED / READY
├─ WARNING
├─ QUARANTINED
├─ REJECTED / FAILED
├─ INVALIDATED
└─ ARCHIVED
```

| `ops.request_slice` | RequestSlice | 保留切片树、Lease和幂等 |
| `ops.slice_attempt` | SliceAttempt | 每次真实请求独立记录 |
| `ops.data_watermark` | DataWatermark | 作为汇总，不替代批次事实 |
| RAW表 | RawBatch和RawRecord | 继续按DataItem管理 |
| CLEAN表 | CleanBatch和CleanRecordVersion | 补齐版本和可用时间 |
| QUALITY表 | QualityRun、Issue和Gap | 保留质量门禁 |
| `audit.audit_event` | AuditEvent | 扩展状态和高风险动作 |
| `lineage`空schema | 追溯能力缺口 | P2后续必须建设 |
| Feature以后对象 | 目标对象 | V1-C建设 |
| Strategy、Backtest以后对象 | 目标对象 | V1-D建设 |
| Signal、Decision以后对象 | 目标对象 | V1-E建设 |
| Execution以后对象 | 目标对象 | V2、V3建设 |

## 20. 禁止事项

后续设计和开发禁止：

- 用一张通用表承载全部业务对象；
- 把所有状态都压缩成成功和失败；
- 用日志代替正式状态；
- 用当前最新版替代历史版本；
- 让回测直接引用可变策略代码；
- 让信号直接等于订单；
- 让用户决策覆盖系统信号；
- 让外部ID成为平台主键；
- 让AI直接修改正式数据库状态；
- 让旧quantStock成为新平台长期依赖；
- 在没有真实需求时建设通用工作流引擎。

## 22. P2.2完成标准

本专题完成后，平台能够明确回答：

1. 每个核心业务对象是什么；
2. 当前哪些对象已经实现；
3. 哪些对象只是目标设计；
4. 哪些对象有稳定身份；
5. 哪些对象必须有不可变版本；
6. 哪些对象代表一次执行；
7. 哪些对象代表结果集合；
8. 每类对象允许哪些状态；
9. 单用户阶段如何预留归属；
10. V1和V2、V3对象边界如何隔离。

## 23. 最终结论

P2.2确定：

```text
稳定对象
+
不可变版本
+
独立执行记录
+
明确结果批次
+
统一状态
+
归属和环境
+
全链路引用
```

作为平台长期对象基线。

现有数据底座继续复用，但必须补齐正式血缘、数据快照和上层研究对象，不能把当前46张数据表直接当成完整业务平台。
