# 1. 复核依据

P3目标：

```text
建立可配置、可追踪、可补采、可扩展的数据接入入口
```

路线图P3主要要求：

- 首批和最终数据域清单；
- 每个数据项的来源、字段、粒度、历史范围和更新时间；
- 数据源生命周期；
- 数据目录和数据项级配置；
- 历史初始化；
- 增量更新；
- 指定范围补采；
- 限频；
- 重试；
- 断点续传；
- 幂等；
- RAW原始数据保存；
- Token与敏感配置；
- 采集状态；
- 日志和异常；
- 主源、备用源和扩展规则。

P3完成门槛：

```text
首批数据可以自动初始化和持续更新
任务失败后可定位、可重试、可补采
同一范围重复运行不会产生不可控重复数据
每批原始数据可追溯到来源、接口、参数和采集时间
数据目录和实际接入能力一致
```

# 5. 旧quantStock边界复核

P3没有继承旧quantStock运行架构。

正式边界：

```text
旧quantStock
=
遗留资源来源
```

允许：

- 历史数据盘点；
- 只读校验；
- 受控迁移；
- 经验复用。

禁止：

- 新项目直接使用旧数据库作为正式业务库；
- 新项目复用旧任务状态；
- 新项目依赖旧Worker；
- 新项目依赖旧Redis；
- 新项目直接继承旧容器网络。

因此旧项目停机后：

```text
不得影响quantStock1正常运行
```
