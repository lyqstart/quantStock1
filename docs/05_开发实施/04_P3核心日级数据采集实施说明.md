# P3核心日级数据采集实施说明

> 版本：0.4.0  
> 日期：2026-07-27  
> 状态：待真实环境验证

## 本批实施范围

在已经真实验证通过的 `trade_calendar`、`stock_basic`、`stock_daily` 基础上，继续接入：

- `stock_adj_factor` → Tushare `adj_factor`
- `stock_daily_basic` → Tushare `daily_basic`
- `stock_suspend` → Tushare `suspend_d`
- `stock_limit_price` → Tushare `stk_limit`

## 实施方式

四个DataItem继续复用统一链路：

```text
TaskDefinition
→ Scheduler
→ CollectTask
→ RequestSlice
→ Worker
→ TushareAdapter
→ RawBatch
→ RAW
→ DataWatermark
```

没有为四个接口新增独立Worker或独立调度框架。

## 调度规则

- `stock_limit_price`：来源约08:40更新，平台09:00前后即可进入当日增量窗口，当前配置为08:50后。
- `stock_adj_factor`：来源盘前完成当日数据入库，当前平台配置09:30后。
- `stock_daily_basic`：来源15:00～17:00更新，当前平台配置17:10后。
- `stock_suspend`：来源官方更新时间不定期，不假设固定时刻；第一阶段使用次日回看前一交易日的保守策略。

## 数据完整性保护

- `adj_factor`、`daily_basic`、`stk_limit`：交易日返回0行视为异常，进入重试。
- `suspend_d`：0行是合法结果，因为某交易日可能没有停复牌事件。
- 达到接口单次返回上限仍触发 `POSSIBLE_TRUNCATION`，不能静默当作完整数据。
- RAW继续按 `_source + _source_api + _content_hash` 幂等去重。
- 全市场批量写入继续按1000行拆批，避免单SQL参数过大。

## 当前边界

本文件只表示代码已经实现，不表示真实环境已经验收通过。
真实Tushare权限、返回条数、RAW入库和任务状态仍需在 `svr3` 开发环境实际验证。


## stk_limit 分页修正（2026-07-27）

真实环境验证中，`stk_limit` 单日全市场返回达到官方单次上限 5800 条。系统按完整性保护规则拒绝直接落库，任务状态为 `POSSIBLE_TRUNCATION`。

修正后：

```text
第一页 offset=0, limit=5800
↓ 满5800条
自动生成下一页 offset=5800
↓
持续分页，直到返回不足5800条
↓
任务完成
```

每一页仍是独立 `RequestSlice`，因此每一次真实外部调用继续保留独立的 Slice/Attempt 追踪，不放宽完整性保护规则。原失败任务保留为历史事实，通过新的 `RERUN` 任务完成验证。
