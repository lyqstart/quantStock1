## 2. 已实现能力

### 2.1 Worker运行状态

Worker启动后登记 `ops.worker_registry`，运行期间持续更新心跳；正常退出标记 `OFFLINE`。

Worker异常退出时，已有Slice Lease机制负责识别失联执行并把未完成工作重新放回可执行队列。

### 2.2 Scheduler运行状态

Scheduler每次扫描记录：

- 实例ID；
- 环境；
- 版本；
- 心跳；
- 最近扫描时间；
- 下次扫描时间；
- LEADER/STANDBY/OFFLINE状态。

单Leader仍由PostgreSQL advisory lock保证。

### 2.3 运维查询API

新增：

```text
GET /api/v1/ops/overview
GET /api/v1/ops/data-items
GET /api/v1/ops/tasks
GET /api/v1/ops/tasks/{task_id}
GET /api/v1/ops/workers
GET /api/v1/ops/scheduler
```

用途：不翻日志即可查看系统、数据项、任务、Worker和Scheduler运行状态。

### 2.4 受控写操作API

新增：

```text
POST /api/v1/ops/backfills
POST /api/v1/ops/tasks/{task_id}/retry
POST /api/v1/ops/tasks/{task_id}/pause
POST /api/v1/ops/tasks/{task_id}/resume
POST /api/v1/ops/tasks/{task_id}/cancel
```

长任务API只创建或控制任务，不在HTTP请求内执行真实采集。

### 2.5 Retry语义

Retry不修改旧Run历史。

```text
Run-001 FAILED
↓ 人工Retry
原Task重新PENDING
↓
Run-002执行
```

旧失败Run仍保留，最终Task可以完成。

### 2.6 Pause / Resume

暂停后：

- 不再领取该Task新的Slice；
- 当前已执行请求允许安全结束；
- 恢复后只继续未完成Slice。

### 2.7 Cancel

取消后：

- PENDING/RETRY_WAIT Slice转为CANCELLED；
- 不再领取新Slice；
- 已写RAW不删除；
- 正在执行的请求安全结束后不把Task重新改为成功。

### 2.8 AuditEvent

新增 `audit.audit_event`。

当前记录：

- Backfill创建；
- Retry；
- Pause；
- Resume；
- Cancel。

保留操作对象、前后状态、原因、操作者、Trace和时间。

## 4. 架构保持不变

```text
PostgreSQL

API
+
Scheduler
+
统一Worker
```

- Celery；
- RabbitMQ；
- Kafka；
- Redis核心依赖；
- Airflow式DAG。
