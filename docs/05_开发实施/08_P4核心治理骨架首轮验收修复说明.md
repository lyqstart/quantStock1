# P4核心治理骨架首轮验收修复说明

> 版本：0.7.1  
> 日期：2026-07-28

## 1. 首轮真实验收结果

P4-1 0.7.0 首轮真实验收中，三个发布单元均被质量门禁阻断：

```text
trade_calendar|BLOCKED|BLOCKED|208/208
stock_basic|BLOCKED|BLOCKED|5870/5871
stock_daily|BLOCKED|BLOCKED|0/0
```

精确问题：

```text
trade_calendar
QB-CAL-003 CALENDAR_RANGE_GAP
计划范围按错误时区形成209天，实际RAW为208天。

stock_basic
QB-CLEAN-001 CLEAN_REJECTED_ROWS
Tushare RAW存在历史特殊代码 T600018.SH / 上港集箱(退)。

stock_daily
QB-DAY-003 INVALID_TRADE_DATE
手工 enqueue-clean-latest 选中了成功但零行的采集任务；同时交易日历尚未发布。
```

## 2. 修复决策

### 2.1 交易日历业务日期

`CollectTask.time_start/time_end` 必须先转换为 `Asia/Shanghai`，再提取业务日期。

禁止直接对数据库返回的时区时间调用 `.date()`。

### 2.2 latest RAW 选择

`enqueue-clean-latest` 只允许选择同时满足以下条件的采集任务：

```text
CollectTask.status = SUCCEEDED
存在 RawBatch.status = SUCCEEDED
存在 RawBatch.row_count > 0
```

避免成功但零行的任务进入 CLEAN。

### 2.3 历史特殊证券代码

`T600018.SH` 是来源正式返回的历史退市记录，但不符合 quantStock1 canonical `security_code` 规则。

处理：

```text
RAW：保留
CLEAN：SKIP
reason_code：HISTORICAL_SOURCE_CODE
质量：不作为REJECT/BLOCK
```

禁止：

```text
T600018.SH → 600018.SH
```

因为这会改变来源身份，并可能与标准证券身份发生冲突。

### 2.4 SKIP追溯

新增：

```text
clean.clean_skipped_row
```

用于保存：

```text
clean_batch_id
raw_batch_id
raw_record_id
source_record_key
reason_code
details
```

使 `SKIP` 可计数、可追溯，不静默丢弃。

### 2.5 零候选保护

新增 BLOCK：

```text
QB-CLEAN-002 ZERO_CANDIDATE_ROWS
```

非空 RAW 输入生成零条 canonical CLEAN 时必须阻断。

新增计数一致性 BLOCK：

```text
QB-CLEAN-003 NORMALIZATION_COUNT_MISMATCH
```

要求：

```text
raw_rows = accepted_rows + skipped_rows + rejected_rows
```
