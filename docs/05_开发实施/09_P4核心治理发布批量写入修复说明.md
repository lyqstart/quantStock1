# P4核心治理发布批量写入修复说明

## 1. 问题

P4-1 第二轮真实验收中，`stock_basic` 已完成标准化，QUALITY 发布阶段失败：

```text
WRITE_FAILED
sending query and params failed: number of parameters must be between 0 and 65535
```

数据库事实证明该问题发生在标准数据发布写入阶段，不属于数据质量 BLOCK。

## 2. 根因

P4 发布代码使用单条 PostgreSQL `INSERT ... ON CONFLICT DO UPDATE` 写入全市场数据。

`stock_basic` 一次约 5870 行，每行包含多个字段，单条 SQL 的绑定参数总数超过 PostgreSQL 驱动单次 65535 参数边界。

同样风险也存在于约 5526 行的 `stock_daily` 正式发布。

## 3. 修复

P4 正式发布写入统一按每批 1000 行执行：

```text
全市场候选数据
↓
1000行/批
↓
多条幂等 UPSERT
↓
同一数据库事务提交
```

因此只是拆分 SQL，不拆分 CleanBatch，也不改变发布原子性。

## 4. 版本

```text
应用版本：0.7.2
数据库迁移：无新增迁移，仍为 0010_p4_skip_audit
```

## 5. 自动验证

新增验证：

- 5870 行按 1000 行切为 6 批；
- 5526 行 `stock_daily` 发布生成 6 条 UPSERT；
- 非法批大小拒绝执行。

本修复完成后重新执行 P4-1 真实验收。
