# P4日线重洗规则版本升级修复说明

> 版本：0.7.5  
> 日期：2026-07-28

## 1. 现象

0.7.4 已将日线成交量“手→股”的换算改为十进制精确计算，但重新执行后仍显示旧的 `5046/5526、reject=480` BLOCK 结果。

## 2. 根因

P4 清洗任务的幂等身份包含来源任务、scope、`mapping_version`、`normalization_version` 和 `quality_rule_version`。

0.7.4 改变了标准化结果，却仍使用 `normalization-v2`，所以同一 RAW 和 scope 被识别成旧规则的重复任务，旧 BLOCK CleanBatch 被复用，新代码没有真正执行。

## 3. 修复

正式升级：

```text
normalization-v2 → normalization-v3
0.7.4 → 0.7.5
```

`mapping-v1` 不变，因为字段映射没有变化。

`quality-v2` 不变，因为质量门禁语义没有变化。

不把 `app_version` 加入幂等键，因为普通代码升级不应无条件触发全量重洗。

## 4. 预期结果

再次创建 `stock_daily 2026-07-24` CLEAN 时，系统必须生成新的 normalization-v3 任务和 CleanBatch，5526 条 RAW 使用十进制精确换算，`reject=0`，随后进入 QUALITY 并正式发布。

## 5. 治理规则

以后凡是会改变 CLEAN 业务结果的标准化逻辑修改，都必须升级 `normalization_version`，不能只升级应用版本。
