# P4涨跌停价格可选昨收字段修复说明

> 阶段：P4-2
> 版本：0.8.1
> 质量规则版本：quality-v3
> 日期：2026-07-28

## 1. 现象

2026-07-27 `stock_limit_price` 真实验收：

```text
RAW=7709
ACCEPT=5533
SKIP=2176
REJECT=0
QUALITY=BLOCKED
QB-LIMIT-002=INVALID_LIMIT_PRICE
```

进入 A 股 CLEAN 范围的 5533 条记录中：

```text
pre_close=NULL: 10
up_limit=NULL: 0
down_limit=NULL: 0
```

## 2. 根因

`stk_limit.pre_close` 是可选字段。

原 `QB-LIMIT-002` 错误地要求：

```text
pre_close/up_limit/down_limit 三个字段全部非空
```

因此 10 条有效股票记录因为 `pre_close=NULL` 被整体质量门禁阻断。

## 3. 修复

质量规则调整为：

```text
pre_close:
  NULL -> 合法
  非NULL -> 必须有限且 > 0

up_limit/down_limit:
  必须存在
  必须有限
  必须满足 up_limit > down_limit
```

不修改 RAW，不填补缺失的 `pre_close`，不推测昨收价。

`920176.BJ` 的源数据：

```text
pre_close=22.16
up_limit=99999.99
down_limit=0
```

原规则和修复后的规则都不会因为 `down_limit=0` 单独阻断该记录；本次 BLOCK 根因不是该记录。

## 4. 版本治理

质量规则发生变化：

```text
quality-v2 -> quality-v3
```

应用版本：

```text
0.8.0 -> 0.8.1
```

用于确保已有 BLOCK 批次能够生成新的 QualityRun，而不是被任务幂等复用。

## 5. 验证

新增测试覆盖：

```text

920176.BJ 当前源边界值允许通过
up_limit/down_limit 缺失继续 BLOCK
up_limit <= down_limit 继续 BLOCK
quality_rule_version=quality-v3
```
