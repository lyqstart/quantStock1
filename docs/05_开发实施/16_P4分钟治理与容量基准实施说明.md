# P4分钟治理与容量基准实施说明

> 阶段：P4-3
> 版本：0.9.0
> Alembic：0012_p4_minute_governance

## 1. 本批目标

本批先建立可验证的分钟 CLEAN、质量门禁、血缘和容量测量能力，不进行全市场分钟历史初始化。

首个真实验收样本固定为：

```text
000001.SZ
2026-07-24
1min
已知RAW样本：241条
```

## 2. 正式分钟 CLEAN

新增：

```text
clean.stock_minute
```

标准主键：

```text
security_code + frequency + trade_time
```

字段仅保留：

```text
security_code
frequency
trade_time
open/high/low/close
volume_share
amount_cny
_clean_batch_id
```

高频事实行不重复保存来源、映射版本、质量版本等批次级治理字段，这些信息通过 `_clean_batch_id` 追溯。

## 3. 时间和单位口径

正式第一阶段频率：

```text
1min
```

来源分钟时间按 `Asia/Shanghai` 解释，CLEAN 使用 `timestamptz`。

P3 已确认的普通交易日 Tushare 1分钟样本语义为：

```text
09:30 - 11:30
13:01 - 15:00
合计241个时间点
```

当前会话规则版本：

```text
cn-a-minute-session-v1
```

不推测特殊交易日时段；如发现真实例外，必须以新规则版本治理。

分钟来源单位：

```text
vol    = 股
amount = 元
```

因此分钟数据不执行日线的“手→股”或“千元→元”换算。

## 4. 分钟质量门禁

分钟发布单元：

```text
security_code + frequency + trade_date
```

BLOCK 检查至少包括：

```text
重复业务键
无效交易日
未知证券
正式时段外时间点
缺失正式时间点
OHLC无效
OHLC高低关系错误
负成交量
负成交额
完整分钟OHLC与正式日线冲突
```

分钟成交量、成交额汇总与日线不一致现阶段只记 WARN。原因是来源覆盖口径尚需真实数据继续验证，不能在证据不足时做强制 BLOCK。

## 5. TimescaleDB

`clean.stock_minute` 在迁移中转换为 TimescaleDB hypertable：

```text
时间维度：trade_time
空间分区：无
```

本批不写死最终 chunk interval。

数据库扩展自身的默认时间间隔只是临时物理状态；正式 `StoragePolicy.chunk_interval` 保持 NULL，直到服务器容量实测完成。

本批不启用自动压缩/columnstore，不创建 continuous aggregate。

## 6. StoragePolicy

新增：

```text
meta.storage_policy
```

首批登记：

```text
stock_minute.raw
stock_minute.clean
```

RAW 当前仍为普通 PostgreSQL 表。其 `trade_time` 是来源文本字段，RAW hypertable 改造涉及来源主键和时间字段迁移，因此必须在真实容量与迁移风险验证后单独实施，不在本批直接转换。

CLEAN 已作为 Timescale hypertable，用于实际写入与容量测量。

## 7. 容量报告

新增命令：

```text
python -m app.cli minute-storage-report --date YYYY-MM-DD
```

输出至少包含：

```text
数据库总字节数
RAW行数
RAW表/索引/总字节数
CLEAN行数
CLEAN表/索引/总字节数
CLEAN覆盖交易日数
是否为hypertable
实际时间维度与当前物理interval
```

这些数据将作为下一步确定：

```text
bytes/day
index bytes/day
合理chunk interval
压缩测试窗口
全市场分钟初始化是否允许启动
```

的证据。

## 8. 血缘

分钟行仅保存 `_clean_batch_id`，但必须能沿以下链路回溯：

```text
stock_minute row
→ CleanBatch
→ QualityRun
→ CleanRun
→ RawBatch
→ CollectRun
→ CollectTask
→ SourceBinding
```

API 补充分钟业务键：

```text
security_code
frequency
trade_time
```

## 9. 本批明确不做

```text
不进行全市场分钟历史初始化
不批准最终chunk interval
不启用自动压缩/columnstore
不启用自动分钟RAW删除
不建立5/15/30/60分钟长期副本
不建立continuous aggregate
```

这些决策必须等真实容量基准后再做。
