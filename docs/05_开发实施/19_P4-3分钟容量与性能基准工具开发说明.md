# P4-3 分钟容量与性能基准工具开发说明

> 日期：2026-07-28
> 状态：开发完成，待服务器真实验证
> 目标版本：0.9.3
> 数据库迁移：无
> 基准版本：minute-benchmark-v1

## 1. 开发目标

P4-3 已经完成分钟 RAW、CLEAN、QUALITY、PUBLISHED 主链和北交所质量口径修复。下一项开发任务是建立可重复执行的分钟数据容量与查询性能基准工具，为后续存储策略决定提供真实证据。

本轮开发不是决定最终存储参数，而是建设测量能力。

## 2. 现有能力和缺口

仓库已有 `minute-storage-report`，能够统计：

- RAW 和 CLEAN 行数；
- 数据表、索引和总占用；
- TimescaleDB hypertable 状态；
- 当前时间分块间隔。

现有命令不能回答：

- 当前样本是否足以推算全市场容量；
- 每行数据和索引的实际平均占用；
- 全市场单日和年度容量的临时投影；
- 单股单日、全市场单日、单股区间查询的实际耗时；
- 查询是否发生磁盘读取或临时文件使用；
- 当前 chunk 和压缩状态；
- 当前证据是否允许修改 chunk interval、启用压缩或开始全市场历史初始化。

## 3. 新增能力

新增命令：

```text
minute-capacity-benchmark
```

输入参数：

- 目标交易日；
- 代表性股票代码；
- 分钟频率；
- 区间查询开始和结束日期；
- 预计全市场股票数量；
- 年交易日数量；
- 每只股票每日分钟点数；
- 查询重复次数。

输出内容：

### 3.1 容量

- 数据库总大小；
- RAW 行数、表大小、索引大小和总大小；
- CLEAN 行数、表大小、索引大小、TOAST 和总大小；
- 每行平均占用；
- 预计全市场单日行数；
- 预计全市场单日容量；
- 预计年度容量；
- 目标交易日实际覆盖比例。

### 3.2 样本充分性

基准工具根据以下最低条件标记样本状态：

- 至少达到一个预计全市场交易日的行数；
- 至少覆盖 3 个交易日。

未达到时返回：

```text
sample_readiness.status=PROVISIONAL
```

这表示容量投影仅用于确定下一轮扩大样本规模，不能据此修改正式存储策略。

### 3.3 查询性能

重复执行并统计最小值、中位数和最大值：

1. 单只股票单日分钟明细；
2. 全市场单日按股票汇总；
3. 单只股票指定区间按交易日汇总。

同时记录：

- 规划耗时；
- 执行耗时；
- 实际返回行数；
- 执行计划根节点；
- 缓存命中块；
- 磁盘读取块；
- 临时读写块。

### 3.4 TimescaleDB 状态

- chunk 数量；
- 已压缩 chunk 数量；
- 最早和最晚 chunk 范围；
- 已建索引定义；
- `StoragePolicy` 当前配置。

### 3.5 决策保护

工具只采集证据，不修改数据库结构和策略。输出中固定包含：

```text
chunk_interval_change_allowed=false
compression_enable_allowed=false
full_market_history_allowed=false
```

只有形成独立决策文档并完成受控验证后，才允许改变这些边界。

- Alembic：保持 `0012_p4_minute_governance`；
- 数据库迁移：无。

## 6. 本轮不做

- 不调整当前 7 days 物理 chunk interval；
- 不启用 TimescaleDB 压缩；
- 不修改 `StoragePolicy`；
- 不做全市场分钟历史初始化；
- 不自动生成虚构数据；
- 不把当前 24341 条样本投影直接认定为最终容量结论。

## 7. 下一步真实验证

部署 0.9.3 后，先对现有 2026-07-24 样本运行基准，验证：

1. 命令输出结构完整；
2. 当前样本被正确标记为 `PROVISIONAL`；
3. 三类查询均能返回真实执行计划和耗时；
4. chunk interval 仍为 7 days；
5. compressed chunks 仍为 0；
6. 所有决策保护开关均为 false；
7. 服务运行状态不受影响。

现有样本验证通过后，再根据结果确定下一轮扩大样本的股票数量和交易日数量。
