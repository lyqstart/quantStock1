# 6. RAW 幂等批次选择问题

P3 RAW 已经具备幂等去重。

因此重复采集可能出现：

```text
接口返回5526条
RawBatch.row_count=5526
实际新增RAW物理行=0
```

P4 原逻辑错误地只看：

```text
RawBatch.row_count
```

导致 CLEAN 选择了物理空批次。

修复后：

```text
CLEAN输入必须确认对应RAW表中存在真实物理记录
```

因此 P4 会选择最近一个真正持有目标 RAW 数据的成功采集批次。

# 7. 日线成交量浮点误判

首次真实日线清洗：

```text
raw=5526
accept=5046
reject=480
```

调查结果：

```text
vol_float_fraction=465
ah_vol_float_fraction=19
```

其中部分记录同时命中，最终对应：

```text
480条误拒绝
```

原因：

```text
Python二进制浮点数 ×100
产生微小表示误差
```

合法的：

```text
12345.67 手
```

可能不能被二进制浮点精确表示。

旧判断：

```text
float(value) * 100
必须 is_integer()
```

会误判。

修复：

```text
使用十进制精确运算
```

规则本身没有放宽：

```text
只有 ×100 后确实能够成为整数股
才允许进入CLEAN
```

最终：

```text
5526 / 5526
reject=0
```
