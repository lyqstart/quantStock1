# 4. pre_close 可选字段问题

首次质量检查：

```text
stock_limit_price
BLOCKED
5533/7709
skip=2176
reject=0
QB-LIMIT-002
INVALID_LIMIT_PRICE
```

真实数据调查：

```text
accepted_scope=5533
pre_null=10
down_le_0=1
up_le_0=0
```

10 条标准证券存在 `pre_close=NULL`。

结论：

```text
pre_close 是来源可选字段
NULL 本身不能构成 BLOCK
```

修复后的质量规则：

```text
pre_close：有值时才检查合法性
up_limit/down_limit：继续执行必要的价格关系检查
```

质量规则版本：

```text
quality-v2 → quality-v3
```

# 6. 质量规则升级后的重质检闭环

质量规则升级到 `quality-v3` 后，系统最初仍显示旧 `quality-v2 / BLOCKED`。

原因：

```text
旧 CLEAN 任务已经幂等完成
新的质量规则没有自动为既有 CleanBatch 创建新的 QualityRun
```

最终修复：

```text
已存在 CleanBatch
+
当前质量规则版本变化
↓
直接创建新的 QUALITY 任务
↓
生成新的 QualityRun
↓
更新 CleanBatch 当前质量状态
```

最终证明：

```text
quality_runs=2
quality-v3
PUBLISHED / PASSED
```

因此一份 CleanBatch 可以接受多次版本化质量检查，符合 P4 设计。
